# 計算規則

> **修改 `js/calc.js`，或任何和金額、餘額、支出合計、評等有關的程式前，請先讀完這份文件。**
> 這些規則是這個專案最容易被改壞的地方。

罐子餘額不儲存，每次都由紀錄即時計算（`stats()`、`jarStats()`）。所以修改每月金額或過去的紀錄後，所有月份都會重新計算。

用語：
- **個人罐子**：`S.buckets` 中的罐子。
- **共用罐**：Firestore `jars/{jarId}`，程式中以 `sj:<jarId>` 表示。
- **所屬罐子**：共用罐屬於自己的哪個個人罐子（`jarPlan.hist[].src`）。每月撥款與超支份額都從這個罐子出。
- **花費型／儲蓄型**（v43，`kind`）：每個個人罐子屬於其中一種。
  - 花費型（`'spend'`）：用來花的錢。預設月底歸零；勾選「沒花完的錢留到下個月」（`carry:true`）時會結轉。新增的罐子預設為花費型、月底歸零。
  - 儲蓄型（`'save'`）：用來存的錢，一定結轉（`carry:true`）。
  - **會結轉**（`carries()`）= 儲蓄型，或勾選留到下個月的花費型，或 `excessTo`／`sweepTo` 指定的罐子。
  - 類型只決定「怎麼顯示」與轉移怎麼歸類，餘額只看會不會結轉。共用罐不分類型。

---

## 1. 每月分配

- 收入分成兩種：
  - **依每月計畫分配**（`mode:'pct'`）：同一個月的這類收入先加總（`planTotals()`），再依計畫分配（`planAlloc()`）。
  - **全部放入一罐**（`mode:'one'`）：整筆放入 `target`，不參與計畫。
- `planAlloc(T, 月份)`，其中 T 是當月計畫收入的合計，P 是所有罐子每月金額 `amt` 的合計：
  - **T ≥ P**：每個罐子拿到自己的 `amt`，多出來的 T − P 放入 `excessTo`。
  - **T < P**：依 `amt` 等比例分配給 `amt > 0` 的罐子。最後一個罐子拿剩下的零頭，所以合計剛好等於 T。
  - **P = 0**（沒有設定任何每月金額）：全部放入 `excessTo`。
- 單筆收入的分配（`incAlloc()`）是「當月分配結果 × 這筆收入 ÷ 當月計畫收入合計」，只用於顯示與 CSV。
- **即時重算**：修改罐子的每月金額，所有月份都會依新的金額重新分配（沒有「從某月起生效」）。
- 收入分到的錢，算在罐子當月的「本月進」。

## 2. 逐月推進（`stats()`）

`stats(excludeId, month)` 從最早有紀錄的月份算到 `month`，每個月依序執行：

1. **本月餘額 = 上月結轉 + 本月進 − 本月出**
   - 本月進：分配到的收入、全部放入這罐的收入、轉入。
   - 本月出：支出、轉出，以及**撥給共用罐的錢**：
     - 每月撥款（`jarContrib()`）。
     - 自己寫入共用罐的 `cover` 紀錄（共用罐超支時自己的份額，見第 5 節）。v39 起在這一步扣除。

     這兩項都算**所屬罐子自己的支出**。
2. **超支墊付，不連鎖**
   - 依步驟 1 的餘額，算出每個罐子自己的不足額 `short`。
   - 有 `coverBy` 的罐子補到 $0（顯示 $0 並標示超支），墊付罐子扣掉同樣的金額。
   - 所屬罐子因為撥款或共用罐的超支份額而不足時，和自己花超過一樣，依它的 `coverBy` 墊付。
   - 墊付罐子因為替其他個人罐子墊付而變成負數時，維持負數，**不會**再觸發它自己的 `coverBy`（個人罐子之間不連鎖）。`short` 在墊付之前就算好，所以墊付罐子自己原本的不足，仍會由它的 `coverBy` 墊付。
   - 沒有 `coverBy` 的罐子維持負數：會結轉的罐子把負數帶到下個月；每月歸零的罐子在步驟 3 結算掉。
3. **月底結算**：不會結轉的罐子（月底歸零的花費型），把剩餘或不足（可能是負數）結算進 `sweepTo`，自己歸零。目標月份本身不做這一步（月份還沒結束）。

### 輸出（目標月份，每個個人罐子一筆）

| 欄位 | 說明 |
|---|---|
| `open` | 上月結轉 |
| `monthIn` | 本月進，**不含** `xferIn`。儲蓄型就是「本月存入」 |
| `monthOut` | 自己的支出 + 算在本月的轉出，**不含**撥給共用罐的錢與 `xferOut` |
| `xferIn`、`xferOut` | 儲蓄型和其他個人罐子之間的轉入、轉出（見下方「儲蓄型的轉移」）；花費型一律是 0 |
| `monthJar` | 每月撥款 |
| `jarCover` | 共用罐的超支份額（`cover`） |
| `jarOut` | `monthJar` + `jarCover` |
| `jarParts` | `[{id:'sj:<jarId>', contrib, cover, amount}]`，依共用罐分開 |
| `bal` | 月底餘額（墊付之後） |
| `short` | 自己的不足額（墊付之前） |
| `over`、`coveredBy` | 被墊付者：被墊付的金額、墊付罐子 |
| `covered`、`coverParts` | 墊付者：替其他**個人罐子**墊付的合計與明細（不含共用罐） |
| `sweep`、`sweepParts`、`sweepMonth` | 只有 `sweepTo`：上個月結算進來的合計、各罐明細、結算的月份 |

### 儲蓄型的轉移（v43，取代 v40 的結轉罐子轉移規則）

只影響「本月」怎麼呈現，**不影響餘額**（`bal`、`short`、墊付、月底結算都不變）。

- 適用範圍：兩個**個人罐子**之間的轉移，**兩邊各自判斷**是否為儲蓄型（`isSave()`）：
  - 轉出方是儲蓄型：這筆轉出計入 `xferOut`，不計入 `monthOut`。
  - 轉入方是儲蓄型：這筆轉入計入 `xferIn`，不計入 `monthIn`（不算本月存入）。
  - 花費型（不論是否留到下個月）的那一邊照舊算在本月。
  - 舊的、手動轉入或轉出共用罐的紀錄不適用，維持原本的計算。
- v40 的「轉出先動用累積、不夠才動用本月份額」（`xferShare`）已移除：儲蓄型不再顯示本月份額與本月剩，轉移不影響本月淨存。

## 3. `excessTo`、`sweepTo` 只能是儲蓄型

- 設定頁的選單只列出儲蓄型罐子。
- 目前是這兩個設定對象的罐子，不能改成花費型：設定頁會提示先在「分配與結算」改到其他儲蓄型罐子。
- `carries()` 仍把 `excessTo`、`sweepTo` 視為結轉（保險，否則錢沒有地方放）；`migrateKind()` 也會把它們設為儲蓄型。
- 兩者找不到（例如罐子被刪除）時，退回最後一個儲蓄型罐子（`fallbackPin()`）；沒有儲蓄型罐子時退回最後一個罐子，並把它改為儲蓄型。
- 每個罐子的 `coverBy` 不能是自己（`coverOf()`）。

## 4. 共用罐的每月撥款

- 從所屬罐子**單向**撥出，不退回。共用罐的餘額一律結轉（`jarStats()`）。
- **修改只從當月起生效**：`setJarPlan()` 在 `hist` 新增（或更新）一筆當月的設定，過去的月份維持原本的金額與所屬罐子，因為共用罐的錢其他成員也在使用。
- v36 起，修改所屬罐子（`src`）會同時改 `coverBy`，兩者一律相同。
- **撥款計算到「可切換的最遠月份」**（`horizon()`：當月，或已經提前記帳的最遠月份）。
- 撥款期間：`jarPlan.from` 起，到 `until` 之前（不再是成員時設定）。所屬罐子已被刪除的月份不撥款。
- **撥款紀錄由每位成員自己的裝置寫入共用罐**（`contrib_{uid}_{月份}`），其他成員因此看得到。不同版本的裝置同時在線時，可能互相覆蓋（尚未加版本保護）。
- v36 起共用罐不能手動轉入、轉出：記帳表單的轉移與「全部放入一罐」只列個人罐子；編輯舊紀錄時保留原本的共用罐選項。舊的轉移紀錄照常計算與 mirror。

## 5. 共用罐超支依人數平分（`jarOver()`）

每位成員的裝置算出的結果必須一致。

- 每個月：
  - B = 上月底餘額（含之前月份的墊付）+ 本月進（**不含**本月 `cover`）− 本月出。
  - **本月新超支** = max(0, −B) − max(0, −上月底餘額)，小於 0 時視為 0。
  - 只平分這個月新產生的超支，之前沒人墊付的缺口不會再拿出來平分。
- **每人份額** = `Math.round(新超支 ÷ 目前成員人數)`。成員人數變動時，過去月份的份額也會跟著重算。
- **寫入 `cover` 紀錄**：自己有墊付的罐子時（`jarCoverSrc()`，從當月起生效；v36 起等於所屬罐子），由自己的裝置寫入 `cover_{uid}_{月份}`（`desiredMirrors()`）。份額為 0 或沒有設定墊付罐子時，刪除這筆紀錄。
- 共用罐把 `cover` 算進帳（`jarIn()`：`contrib`、`in`、`cover` 是進帳）。
- **個人帳本這邊**：
  - 從共用罐讀取「自己寫的 `cover` 紀錄」，從 `srcId` 扣款。
  - 這筆錢算這個罐子自己的支出，在 `stats()` 步驟 1 扣除，因此造成的不足會觸發它的 `coverBy`（v39）。
  - 計入 `jarCover`／`jarParts`，不計入 `covered`／`coverParts`（明細的「本月超支墊付」只列個人罐子之間的墊付）。
  - 退出或刪除共用罐後讀不到這些紀錄，扣款也會消失。
- **尚未墊付** = 份額 − 該成員本月的 `cover` 紀錄。尚未墊付的部分讓共用罐維持負數，並標示成員名稱。
- **v36 資料轉換**（`migrateJarOwner()`，帳本旗標 `jarOwnerV36`，只做一次）：從當月起 `coverBy = src`（在 `hist` 補一筆當月的設定），過去月份不變，所以過去的餘額不變。原本的墊付罐子不同或不墊付時，在 `jarOwnerNote` 記下說明，顯示在通知面板。

## 6. 個人支出的計算方式

v36 起：**個人支出 = 個人罐子的支出（`ownSpend()`）+ 撥給共用罐的錢（`sharedSpend()`：每月撥款 + 超支份額）**。

- 撥款與超支份額算所屬罐子的支出：
  - 明細中由 `jarSpendItems()` 產生支出列：標題是共用罐名稱，副標題是「每月撥款」或「超支墊付」。數字和 `stats()` 的 `jarParts` 一致。
  - 這些金額會計入：
    - 總覽的「這個月支出」（個人 $A + 共用罐 $B）
    - 總覽各罐的本月「用掉」
    - 明細合計與每日支出
    - 圓餅圖：「全部」中每個共用罐是一片；所屬罐子的分類圖中，共用罐是一個分類，key 為 `sj:<jarId>`
    - 月結算的支出、分類排行與評等
- 共用罐**內**的共用支出**不計入**個人支出，避免重複計算。篩選共用罐時顯示它的所有紀錄，個人份額 = 金額 ÷ 記錄當下的人數（`split`），僅供參考。
- **顯示和計算分開**（v38）：
  - 總覽「這個月的紀錄」與明細「全部」由 `monthItems(month,'all')` 列出個人紀錄 ＋ 共用罐內的支出（`sharedExpenseItems()`，全額，副標題標示記錄者），**不列**撥款與墊付。
  - 合計仍是 `ownSpend()` + `sharedSpend()`。每日標題的「支出」只加總個人支出，共用罐的金額另以淡色（`.dsh`）標示。
  - 篩選個人罐子時，列出撥款與墊付（`jarSpendItems()`），不列共用罐內的支出。點撥款或墊付列，會切換到該共用罐的篩選（同月份）。
- 轉移不是支出：轉出算在罐子的 `monthOut`（儲蓄型的轉出改算 `xferOut`，見第 2 節），但不計入「這個月支出」與月結算的支出。

## 7. 系統紀錄只供顯示

月初結算（上月結轉、上月○○剩餘／不足）、本月超支墊付等系統紀錄只供顯示，不計入明細合計、每日支出與圓餅圖，避免同一筆錢在兩個月份被重複計算。

## 8. 總覽的「本月」數字

大數字一律是月底餘額 `bal`。**任何類型的罐子 `bal` < 0 都視為超支**：紅框、套用墊付規則（第 2 節）、評等算超支（第 9 節）。

### 花費型

- **月底歸零**（預設）：
  - 水位 = `bal` ÷（max(0, `open`) + `monthIn`）。
  - 說明：「每月歸零」，有不足時顯示紅字「超支 $X」。
  - 「這個月各罐」：花了 $B（含撥給共用罐）／ 可用 $A，被墊付時註明，替其他罐子墊付時另起一行註明。
- **留到下個月**：
  - 水位 = `bal` ÷（max(0, 上月留下來的 `open`) + 本月分到 `monthIn`）。
  - 說明：「可用 $X」，X = `bal`；有不足時顯示紅字「超支 $X」。
  - 「這個月各罐」：「本月分到 $A・花了 $B ／ 可用 $C」，`open` > 0 時第二行加註「上月留下 $O」（`open` < 0 時紅字「上月不足」）。
  - 轉入、轉出都算在本月（`monthIn`、`monthOut`），不套用儲蓄型的轉移規則。

### 儲蓄型（`saveView()`）

- **本月存入** = `monthIn`：計畫分配、收入超過計畫的部分、全部放入這個罐子的收入。
  - 不含轉入、轉出（`xferIn`、`xferOut`）。
  - 不含上月歸零罐子結算過來的剩餘：那在月初已經算進 `open`，屬於上月帶過來。
- **本月墊付** = `covered`（替其他個人罐子墊付）。
- **本月支出** = `monthOut` + 撥給共用罐的錢（`jarOut`）。
- **本月淨存** = 本月存入 − 本月墊付 − 本月支出。轉移不影響這個數字。
- 水位看累積：`bal` ÷（max(0, `open`) + 本月存入 + `xferIn`），限制在 0%～100%；分母和 `bal` 都是 0 時才顯示「空」。有目標金額的罐子改看目標（見下方「儲蓄目標」）。
- 罐子說明（一行，依序判斷）：
  0. 自己超支、被墊付（`over` > 0）：紅字「超支 $X」。
  1. 本月有存入、墊付或支出：淨存 ≥ 0 顯示「本月淨存 $X」；< 0 顯示紅字「本月淨減 $X」（只有紅字，不是超支紅框）。
  2. 只有轉移：「本月轉入 $X」或「本月轉出 $X」（兩者都有時一起列出）。
  3. 都沒有：「累積中」。
- 「這個月各罐」：
  - 第一行：「本月存入 $A・墊付 $B・支出 $C ／ 本月淨存 $N」，只列有的項目；本月沒有存入、墊付、支出時不顯示這一行。
  - 第二行：「累積 $T」，有轉移時加註「本月轉入 $I・轉出 $X」。
  - 進度條依水位顯示。
- 不再顯示「本月剩」「本月超用」。v30 的本月份額只用於共用罐；v40、v41 為結轉罐子做的處理已整合進這裡。

### 儲蓄目標（v44）

由 `goalView()` 計算顯示、`checkGoals()` 判斷達成提示（`js/views/home.js`）。

- 只有儲蓄型的個人罐子可以設定目標金額 `goal`（共用罐沒有）。空白或 0 表示沒有目標。改成花費型時保留 `goal` 但不使用，改回儲蓄型時恢復。
- 目標金額只影響顯示，**不影響任何餘額**。
- 有目標時（G = `goal`，T = `bal`）：
  - 大數字仍是 T；水位 = T ÷ G，限制在 0%～100%（T < 0 時為 0%，並維持超支紅框與墊付規則）。
  - **達成** = T ≥ G。罐子上的百分比顯示「🎯 19%」，達成時「🎉 100%」；沒達成時最多顯示 99%（避免四捨五入成 100%）。
  - 罐子說明維持上面的規則（超支／本月淨存／本月淨減／本月轉入、轉出／累積中），不被目標取代。
  - 「這個月各罐」第一行不變；第二行改為「累積 $T ／ 目標 $G，還差 $D」（D = G − T），達成時「累積 $T ／ 🎉 已達成目標 $G」，不加註本月的轉入、轉出。進度條和水位一致。
- **達成提示**：一律用**當月**（`curMonth()`）的 `bal` 判斷，和畫面上正在看的月份無關；查看過去或未來月份只改變顯示，不觸發提示。
  - 達成且罐子沒有 `goalReachedAt` 時：提示「○○已達成目標 $G！」，並寫入 `goalReachedAt`（跟著帳本同步，換裝置、重新整理都不會再提示）。
  - 掉回目標以下時清除 `goalReachedAt`，之後再次達成會再提示一次。
  - 修改目標金額時清除 `goalReachedAt` 並重新判斷。
  - 雲端資料完整載入前不判斷（見 [architecture.md](architecture.md#雲端同步)）。兩台裝置同時開著時，可能各提示一次。
- 查看過去月份與月結算時，用的是**目前的**目標金額（目標沒有歷史紀錄）。

### 共用罐（不分類型，維持 v30／v41）

- 水位與「本月剩 $X」反映這個月撥入的錢還剩多少（`monthShare()`），本月剩 < 0 時顯示紅字「本月超用」。
- 這個月沒有撥款、投入或 `cover` 時（`accumView()`），水位改看累積：`bal` ÷（max(0, `open`) + 轉入），說明依序為本月轉出 → 本月支出 → 本月轉入 → 累積中。
- 「撥入」不含本月的超支份額（`cover`），超支份額另外註明。

## 9. 月結算與評等（`js/summary.js`）

- 只有已經結束的月份可以查看月結算。
- `monthData()`：
  - **收入**：當月所有收入（含「全部放入一罐」）。
  - **支出**：個人支出 ＋ 撥給共用罐的錢（每個共用罐是一個分類，🫙）。
  - **結餘** = 收入 − 支出。
  - **超支罐子數**：個人罐子中 `short > 0` 的數量。不論有沒有被墊付都算，也包含撥給共用罐的錢造成的超支；只因替其他個人罐子墊付而變負數的罐子不算。共用罐不列入。
- **罐子成績單**：
  - 花費型：「花了 $A ／ 可用 $B」。
    - 可用 = max(0, 上月結轉) + 本月進（這個月總共能用的錢，轉入算在本月進）。
    - 花了 = `monthOut` + 撥給共用罐的錢（轉出算在 `monthOut`）。
  - 儲蓄型：「本月淨存 $N ／ 累積 $T」，淨存 < 0 時紅字「本月淨減」（定義見第 8 節）。有目標金額時加註「・目標達成 19%」，達成時「・🎉 已達成目標」（v44，用目前的目標金額）。
  - 狀態依 `bal`、`short`、`over` 判斷，不受類型與轉移的分類影響。
- **評等**（`gradeOf()`），結餘率 = 結餘 ÷ 收入：

  | 評等 | 有收入時 | 沒有收入時 |
  |---|---|---|
  | S | 沒有超支，且結餘率 ≥ `sRate`（預設 30%） | — |
  | A | 沒有超支，且結餘率 ≥ `aRate`（預設 10%） | 沒有超支 |
  | B | 超支罐子數 ≤ `bMaxOver`（預設 1），且結餘 ≥ 0 | 超支罐子數 ≤ `bMaxOver` |
  | C | 其他 | 其他 |

- 門檻在開發者選項調整（存在 `S.gradeRules`），所有結算風格共用。
- 評語依月份固定挑選（同一個月每次看到的評語相同）。

## 驗算範例

改到計算邏輯時，用具體數字驗算，並確認**所有罐子的合計等於實際剩下的錢**。

**個人罐子的超支墊付**
- 日常每月 $24,000（每月歸零，`coverBy` = 儲蓄），這個月花了 $26,000。
- 結果：日常顯示 $0，並標示超支 $2,000；儲蓄當月少 $2,000。

**共用罐超支**
- 共用罐有 2 位成員，上月底餘額 $0，本月撥入 $4,000，共用支出 $5,000。
- B = −$1,000，本月新超支 $1,000，每人份額 $500。
- 結果：
  - 自己的裝置寫入 `cover` $500，所屬罐子本月支出多 $500。
  - 對方還沒墊付時，共用罐顯示 −$500，並標示對方尚未墊付。
  - 所屬罐子因此不足時，由它的 `coverBy` 墊付。

**花費型與儲蓄型（v43）**
- 儲蓄（儲蓄型）：上月帶過來 $18,802，本月存入 $20,000，替日常墊付 $1,427，轉出 $18,646 到投資。
  - 本月淨存 = 20,000 − 1,427 = $18,573（轉出不影響）。
  - 累積 = 18,802 + 20,000 − 1,427 − 18,646 = $18,729。
  - 水位 = 18,729 ÷ (18,802 + 20,000) ≈ 48%，說明「本月淨存 $18,573」。
- 投資（儲蓄型，每月分配 $0）：上月帶過來 $0，從儲蓄轉入 $18,646。
  - 說明「本月轉入 $18,646」，水位 100%，累積 $18,646。
  - 下個月沒有任何變動：水位 100%，說明「累積中」。
  - 記一筆投資虧損支出 $2,000：說明紅字「本月淨減 $2,000」，水位 16,646 ÷ 18,646 ≈ 89%。
- 旅遊預算（花費型，留到下個月）：每月分配 $1,000，上月留下 $4,000，本月花 $2,000。
  - 說明「可用 $3,000」，水位 3,000 ÷ 5,000 = 60%。
- 日常（花費型，月底歸零）：顯示與 v42 完全相同。
- 月底歸零的日常轉 $1,000 到儲蓄：日常算在本月；儲蓄的 $1,000 是轉入，不算本月存入，也不影響本月淨存。
- 資料轉換（`migrateKind()`）前後，每個月份每個罐子的 `bal` 必須完全一致。

**儲蓄目標（v44）**
- 儲蓄：累積 $18,729，目標 $100,000。
  - 水位 18,729 ÷ 100,000 ≈ 19%，罐子上「🎯 19%」，說明維持「本月淨存 $18,573」。
  - 「這個月各罐」第二行「累積 $18,729 ／ 目標 $100,000，還差 $81,271」。
- 目標改成 $15,000：立即提示「儲蓄已達成目標 $15,000！」一次，罐子上「🎉 100%」，第二行「累積 $18,729 ／ 🎉 已達成目標 $15,000」；重新整理後不再提示。
- 轉出使累積降到 $15,000 以下，再轉回超過 $15,000：再提示一次。
- 清除目標：恢復第 8 節儲蓄型的顯示。
- 設定目標前後，所有罐子的 `bal` 完全不變。
